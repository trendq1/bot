# IZIDVA AI Trader (PHP) — бот для фьючерсов Bybit с ИИ, Telegram Mini App и админ-панелью

Клиенты заходят в Telegram-бота, открывают мини-апп, бесплатно торгуют на демо-счёте, а по подписке
(Telegram Stars) подключают свой Bybit по вашей реферальной ссылке — бот торгует на их аккаунте.
Вы управляете всем из браузерной админ-панели.

> ⚠️ Торговля фьючерсами с плечом может привести к потере всех средств. Бот не гарантирует прибыль.
> Перед запуском для клиентов проконсультируйтесь с юристом: в ряде стран автоматическая торговля
> на счетах клиентов требует лицензии.

## Как устроено

| Часть | Как работает |
|---|---|
| Сайт: админ-панель, мини-апп, API, Telegram-бот (webhook), `migrate.php` | Обычные PHP-файлы. Работают сразу после загрузки — как любой PHP-сайт |
| Торговый движок `bin/daemon.php` | Постоянный процесс (служба systemd): рынок, сетки, сделки всех клиентов. **Не cron** — работает непрерывно, реагирует за секунды |
| ИИ-аналитик `bin/ai_worker.php` | Запускается движком автоматически отдельным процессом, чтобы запросы к Claude не тормозили торговлю |
| База MySQL / MariaDB | Клиенты, сделки, платежи, настройки, ключи (зашифрованы). Через неё сайт и движок обмениваются командами и состоянием |

## Требования

- PHP **8.1+** с расширениями `pdo_mysql`, `curl`, `openssl`, `mbstring` (в HestiaCP, ISPmanager, aaPanel есть по умолчанию).
- MySQL 5.7+ или MariaDB 10.3+.
- **HTTPS** — Telegram открывает мини-аппы и шлёт webhook только по HTTPS (в панели: Let's Encrypt).
- Для торгового движка — доступ к терминалу сервера **один раз** (VPS). Обычный виртуальный хостинг
  без SSH подойдёт только для сайта: торговля там работать не сможет, это ограничение хостинга, а не PHP.

## Установка

### 1. База данных
Панель → «Базы данных» → создать базу (MySQL, кодировка utf8mb4) и пользователя.
В HestiaCP к имени базы и пользователя добавляется префикс, например `admin_izidva` — запишите полные имена.

### 2. Загрузка файлов
Файловый менеджер → папка сайта (например `public_html`) → загрузить `izidva.zip` → **Распаковать**.
Получится папка `izidva` с `migrate.php`… внутри `public/`, а также `src/`, `vendor/`, `storage/`.

- **Apache** (HestiaCP с Apache, cPanel, большинство панелей): так и оставьте. Служебные папки закрыты
  файлами `.htaccess`, адреса: `https://ваш-домен/izidva/...`.
- **Только nginx**: `.htaccess` не работает — укажите корнем сайта папку `izidva/public`
  (в HestiaCP: Web → домен → Edit → Advanced → Custom document root).

### 3. Мастер установки
Откройте `https://ваш-домен/izidva/migrate.php`:
1. Код установки — в файле `izidva/storage/setup_code.php` (откройте файловым менеджером).
2. Данные базы из шага 1 → «Проверить подключение».
3. Логин и пароль администратора.
4. По желанию сразу: токен бота от @BotFather, ключ Anthropic (можно позже в админке).

«Установить» создаст таблицы, файл `storage/.env` с ключами шифрования и администратора,
подключит webhook Telegram-бота и кнопку меню.

> ⚠️ **Сразу скачайте себе копию `storage/.env`.** Это единственный файл с ключом шифрования — без него
> не восстановить сохранённые токены, ключ Anthropic и ключи Bybit клиентов. При повторной заливке архива
> **не распаковывайте новый zip поверх со сбросом папки** — если файловый менеджер вашего хостинга при
> «Заменить» сначала удаляет старую папку целиком, `.env` пропадёт вместе с ней. Если мастер установки
> при уже существующей базе вдруг предлагает создать нового администратора и предупреждает, что в базе
> уже есть данные, — значит `.env` только что потерялся; лучше остановиться и восстановить его из копии,
> чем продолжать (продолжение сгенерирует новый ключ, и все старые зашифрованные данные станут нечитаемыми).

### 4. Запуск торгового движка (один раз)
Мастер покажет команду — выполните её в терминале сервера:
```bash
sudo bash /home/admin/web/ваш-домен/public_html/izidva/bin/install-service.sh
```
Служба `izidva-engine` будет работать постоянно, перезапускаться при сбое и после перезагрузки сервера.
Больше терминал не нужен: всё остальное — в админ-панели.

### 5. Готово
- Админ-панель: `https://ваш-домен/izidva/admin/`
- Мини-апп: `https://ваш-домен/izidva/app/` (подставляется в настройки автоматически). Интерфейс двуязычный —
  украинский по умолчанию, русский переключается в мини-аппе на вкладке «Налаштування»/«Настройки».
  На вкладке «Сделки» — живой свечной график (Bybit, реальные цены) с отметками входов/выходов клиента
  и текущей позицией/сеткой; обновляется каждые ~4 секунды, пока открыта вкладка.
- В админке «Обзор» → блок «Торговый движок» показывает, работает ли он.

## Обновление версии
1. Загрузите новый архив и распакуйте поверх (папка `storage/` с `.env` сохраняется).
2. Откройте `https://ваш-домен/izidva/migrate.php` (войдя в админку) → «Применить» новые миграции.
3. Админка → Настройки → «Перезапустить торговый движок».

### Ручная торговля и роль «трейдер»

- Роль **администратор** видит всю панель как обычно. Роль **трейдер** после входа видит только раздел
  «Ручная торговля» — остальные разделы и API для неё закрыты (403), даже если знать прямой URL.
- Для клиента можно выключить автотрейдинг («ручной режим») — сетка/тренд/ликвидации перестают открывать
  новые сделки, но уже открытые сетки и позиции движок по-прежнему сопровождает (тейк/стоп, закрытие).
  Включить автотрейдинг обратно можно тем же переключателем.
- Ручной ордер: монета (из списка, с которым работает бот у этого клиента), рынок или лимит с ценой,
  необязательные тейк-профит/стоп-лосс, плечо. Ордер встаёт в очередь и исполняется торговым движком
  (демоном) в течение нескольких секунд — так же, как автоматические сделки, на демо-счёте или на Bybit
  клиента. Статус (в очереди / исполнен / ошибка) обновляется в таблице ниже; лимитный ордер, который ещё
  не исполнился, можно отменить кнопкой «✕».
- **Открыть сразу всем клиентам** — галочка над формой ордера: тот же ордер (монета, сторона, тип, объём,
  тейк/стоп, плечо) ставится в очередь каждому незаблокированному клиенту отдельной строкой; кто сейчас не
  подключён или без биржи — просто получит ошибку по своей строке, остальным ордер всё равно исполнится.
- **Закрыть открытое** — карточка «Открыто у клиента сейчас» показывает все сетки, направленные позиции и
  неисполненные лимитные ордера выбранного клиента с кнопкой «✕ Закрыть»: сетка сворачивается, позиция
  закрывается по рынку, неисполненный лимит снимается с биржи — независимо от того, кто её открыл,
  автостратегия или трейдер.

## Оплата подписки: Telegram Stars + криптовалюта (NOWPayments)

Клиент в мини-аппе на вкладке «Настройки» видит переключатель способа оплаты (появляется только когда
NOWPayments включён) и жмёт тариф — дальше всё автоматически:
клиент выбрал тариф → его перекидывает на страницу оплаты NOWPayments → он платит любой криптовалютой →
NOWPayments присылает вебхук → подписка продлевается и клиент получает сообщение в Telegram. Ручных действий
администратора не требуется.

### Настройка (один раз)
1. Зарегистрируйтесь на [nowpayments.io](https://nowpayments.io), пройдите верификацию.
2. Личный кабинет → **API keys** → создайте ключ.
3. Личный кабинет → **Settings → IPN** → задайте **IPN Secret Key** (это отдельный секрет, не API-ключ).
4. В IPN-настройках укажите callback URL: `https://ваш-домен/izidva/nowpayments/webhook.php`
   (тот же адрес нужно передавать и в каждом инвойсе — бот делает это сам).
5. В админке → **Настройки и ключи** → группа **«NOWPayments (крипта)»**:
   - вставьте **API-ключ** и **IPN Secret Key**;
   - включите переключатель **«Оплата криптовалютой включена»**.

Готово — на вкладке подписки у клиентов появится выбор между ⭐ Stars и ₿ криптовалютой. Цена в долларах
берётся из тех же тарифов, что и Stars (курс — поле «Курс 1 ⭐ в $» в группе «Тарифы»).

### Как это устроено технически
- `MiniApi::pay()` при `method: "crypto"` создаёт инвойс через `POST /v1/invoice` NOWPayments
  (заголовок `x-api-key`) и сохраняет его в таблицу `crypto_invoices` со статусом `waiting`.
- Клиента через `tg.openLink()` (или обычную ссылку) отправляет на `invoice_url` — хостированную страницу
  оплаты NOWPayments, где он платит любой поддерживаемой монетой.
- `public/nowpayments/webhook.php` принимает IPN-вебхуки: проверяет подпись `x-nowpayments-sig`
  (HMAC-SHA512 от рекурсивно отсортированного по ключам JSON тела с IPN Secret Key), обновляет статус
  инвойса, а при статусе `finished` — записывает платёж и продлевает подписку клиенту (та же логика,
  что и для Stars, с защитой от повторного начисления по одному и тому же `payment_id`).
- В админке платежи через крипту помечены тегом «₿ крипта» и попадают в общую статистику доходов наравне
  со звёздами.

## Торговая логика

- **Стратегии:** сетка (много мелких сделок в боковике), тренд (вход после отката к EMA20, тейк 1–1.2R),
  отскок после каскада ликвидаций. На монете одновременно работает одна — с наибольшим весом:
  `вес ИИ × множитель обучения × включена ли у клиента`.
- **ИИ (Claude, официальный PHP SDK):** по каждой монете раз в N минут — режим рынка, веса стратегий,
  направление и шаг сетки, множитель риска. Раз в сутки — разбор сделок, уроки и подстройка параметров
  (±20% за день, в жёстких границах). ИИ не отправляет ордера и не может обойти лимиты риска.
  Без ключа работает запасной алгоритм.
- **Обучение:** по связке «монета × стратегия × режим» копится результат всех клиентов;
  убыточные стратегии получают до 0.4× капитала, прибыльные — до 1.6×.
- **Риск-профили:** консервативный / сбалансированный / агрессивный — риск на сделку 0.3/0.5/1%,
  плечо 3/5/8x, дневной лимит убытка 2/3/5%, ограничение убытка каждой сетки, пауза после серии убытков.
  На маленьком депозите сетка по BTC не строится — минимальный лот не помещается в лимит риска.
- **Досрочный выход при развороте:** тренд- и ликвидационные сделки закрываются по рынку, не дожидаясь
  стопа или тейка, если режим монеты сменился на противоположный тренду позиции (не раньше чем через минуту
  после входа — чтобы не дёргаться от короткого шума). Сеток и ручных сделок трейдера это не касается —
  у сетки своя логика сворачивания, ручные позиции трейдер закрывает сам.
- **Диагностика убытков:** если сделка закрылась с результатом хуже −1.3R (обычный стоп ограничивает
  убыток примерно 1R), это пишется в `storage/logs/app.log` со входом/стопом/выходом/объёмом — повод
  разобрать конкретную сделку, а не совпадение.

## Безопасность
- Ключи Bybit клиентов и ваши ключи шифруются (AES-256-GCM, ключ в `storage/.env`).
- Ключ Bybit с правом вывода отклоняется; реальный счёт — только для ваших рефералов.
- Мини-апп принимает только запросы с подписью Telegram; webhook — только с секретом.
- Админка: пароли bcrypt, подписанная cookie, защита от перебора и CSRF.
- **Храните копию `storage/.env` отдельно** — без него зашифрованные ключи не восстановить.
