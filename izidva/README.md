# IZIDVA AI Trader (PHP) — бот для фьючерсов Bybit с ИИ, Telegram Mini App и админ-панелью

Клиенты заходят в Telegram-бота, открывают мини-апп, бесплатно торгуют на демо-счёте, а по подписке
(Telegram Stars) подключают свой Bybit по вашей реферальной ссылке — бот торгует на их аккаунте.
Вы управляете всем из браузерной админ-панели.

> ⚠️ Торговля фьючерсами с плечом может привести к потере всех средств. Бот не гарантирует прибыль.
> Перед запуском для клиентов проконсультируйтесь с юристом: в ряде стран автоматическая торговля
> на счетах клиентов требует лицензии.

## Как устроено

| Часть | Как работает |
|---|---|
| Сайт: админ-панель, мини-апп, API, Telegram-бот (webhook), `migrate.php` | Обычные PHP-файлы. Работают сразу после загрузки — как любой PHP-сайт |
| Торговый движок `bin/daemon.php` | Постоянный процесс (служба systemd): рынок, сетки, сделки всех клиентов. **Не cron** — работает непрерывно, реагирует за секунды |
| ИИ-аналитик `bin/ai_worker.php` | Запускается движком автоматически отдельным процессом, чтобы запросы к Claude не тормозили торговлю |
| База MySQL / MariaDB | Клиенты, сделки, платежи, настройки, ключи (зашифрованы). Через неё сайт и движок обмениваются командами и состоянием |

## Требования

- PHP **8.1+** с расширениями `pdo_mysql`, `curl`, `openssl`, `mbstring` (в HestiaCP, ISPmanager, aaPanel есть по умолчанию).
- MySQL 5.7+ или MariaDB 10.3+.
- **HTTPS** — Telegram открывает мини-аппы и шлёт webhook только по HTTPS (в панели: Let's Encrypt).
- Для торгового движка — доступ к терминалу сервера **один раз** (VPS). Обычный виртуальный хостинг
  без SSH подойдёт только для сайта: торговля там работать не сможет, это ограничение хостинга, а не PHP.

## Установка

### 1. База данных
Панель → «Базы данных» → создать базу (MySQL, кодировка utf8mb4) и пользователя.
В HestiaCP к имени базы и пользователя добавляется префикс, например `admin_izidva` — запишите полные имена.

### 2. Загрузка файлов
Файловый менеджер → папка сайта (например `public_html`) → загрузить `izidva.zip` → **Распаковать**.
Получится папка `izidva` с `migrate.php`… внутри `public/`, а также `src/`, `vendor/`, `storage/`.

- **Apache** (HestiaCP с Apache, cPanel, большинство панелей): так и оставьте. Служебные папки закрыты
  файлами `.htaccess`, адреса: `https://ваш-домен/izidva/...`.
- **Только nginx**: `.htaccess` не работает — укажите корнем сайта папку `izidva/public`
  (в HestiaCP: Web → домен → Edit → Advanced → Custom document root).

### 3. Мастер установки
Откройте `https://ваш-домен/izidva/migrate.php`:
1. Код установки — в файле `izidva/storage/SETUP_CODE.txt` (откройте файловым менеджером).
2. Данные базы из шага 1 → «Проверить подключение».
3. Логин и пароль администратора.
4. По желанию сразу: токен бота от @BotFather, ключ Anthropic (можно позже в админке).

«Установить» создаст таблицы, файл `storage/.env` с ключами шифрования и администратора,
подключит webhook Telegram-бота и кнопку меню.

### 4. Запуск торгового движка (один раз)
Мастер покажет команду — выполните её в терминале сервера:
```bash
sudo bash /home/admin/web/ваш-домен/public_html/izidva/bin/install-service.sh
```
Служба `izidva-engine` будет работать постоянно, перезапускаться при сбое и после перезагрузки сервера.
Больше терминал не нужен: всё остальное — в админ-панели.

### 5. Готово
- Админ-панель: `https://ваш-домен/izidva/admin/`
- Мини-апп: `https://ваш-домен/izidva/app/` (подставляется в настройки автоматически)
- В админке «Обзор» → блок «Торговый движок» показывает, работает ли он.

## Обновление версии
1. Загрузите новый архив и распакуйте поверх (папка `storage/` с `.env` сохраняется).
2. Откройте `https://ваш-домен/izidva/migrate.php` (войдя в админку) → «Применить» новые миграции.
3. Админка → Настройки → «Перезапустить торговый движок».

## Торговая логика

- **Стратегии:** сетка (много мелких сделок в боковике), тренд (вход после отката к EMA20, тейк 1–1.2R),
  отскок после каскада ликвидаций. На монете одновременно работает одна — с наибольшим весом:
  `вес ИИ × множитель обучения × включена ли у клиента`.
- **ИИ (Claude, официальный PHP SDK):** по каждой монете раз в N минут — режим рынка, веса стратегий,
  направление и шаг сетки, множитель риска. Раз в сутки — разбор сделок, уроки и подстройка параметров
  (±20% за день, в жёстких границах). ИИ не отправляет ордера и не может обойти лимиты риска.
  Без ключа работает запасной алгоритм.
- **Обучение:** по связке «монета × стратегия × режим» копится результат всех клиентов;
  убыточные стратегии получают до 0.4× капитала, прибыльные — до 1.6×.
- **Риск-профили:** консервативный / сбалансированный / агрессивный — риск на сделку 0.3/0.5/1%,
  плечо 3/5/8x, дневной лимит убытка 2/3/5%, ограничение убытка каждой сетки, пауза после серии убытков.
  На маленьком депозите сетка по BTC не строится — минимальный лот не помещается в лимит риска.

## Безопасность
- Ключи Bybit клиентов и ваши ключи шифруются (AES-256-GCM, ключ в `storage/.env`).
- Ключ Bybit с правом вывода отклоняется; реальный счёт — только для ваших рефералов.
- Мини-апп принимает только запросы с подписью Telegram; webhook — только с секретом.
- Админка: пароли bcrypt, подписанная cookie, защита от перебора и CSRF.
- **Храните копию `storage/.env` отдельно** — без него зашифрованные ключи не восстановить.

| Задача | Как |
|---|---|
| Статус движка | админка → Обзор, или `systemctl status izidva-engine` |
| Логи | `storage/logs/app.log` или админка → Журнал |
| Перезапуск движка | админка → Настройки → «Перезапустить», или `systemctl restart izidva-engine` |
| Резервная копия | база (панель → Базы данных → бэкап) + файл `storage/.env` |
